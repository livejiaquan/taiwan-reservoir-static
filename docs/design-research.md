### 觀察

1. **官方給的是表格，民間給的是「一眼看懂」**。官方資料最完整，但不回答「好不好」；民間網站流量大，是因為把狀態轉成圖與顏色。
2. **資料時間各自不同是常態**。水利署與 taiwanstat 都特別註明更新不同步，這次抓 API 也看到同一批資料中，有的水庫停在 05:00、有的已到 15:00。逐列標示時間是必要的，不是裝飾。
3. **好的水情產品都提供「比較基準」**：CDEC／USBR 比歷史平均，BoM 比去年同期，日本公布平年比。水利署這兩個 API 沒有歷史平均，但即時資料包含**過去 24 小時逐時觀測**，足以提供「24 小時變化」與迷你趨勢線。
4. **液態波浪圓形量表不準**：圓形容器裡，水面高度和水的面積不成正比：水位到 25% 高度時，水只佔圓面積約 20%，越靠近底部與頂部越失真；持續的波浪動畫也會干擾閱讀與耗電。茶杯圖有同樣的面積問題。

### 借鏡與改良（皆只借概念，不複製程式碼）

| 借鏡 | 來源 | 在本專案的做法 |
|-----|------|-------------|
| 北／中／南分區 | taiwanstat | 清單依分區分組，並提供分區篩選 |
| 逐站更新時間 | 水利署、taiwanstat | 每列顯示觀測時間；超過 12 小時標示「較舊」 |
| 容器中的水位 | CDEC／USBR 茶杯 | 改用**直立長方形水柱**，水位高度與蓄水率成正比，沒有面積失真 |
| 比較基準 | BoM、日本平年比 | 用 24 小時逐時資料顯示變化量與趨勢線；歷史平均列為未來工作 |
| 只在異常時著色 | 川の防災情報 | 充足與正常都是水藍色，只有偏低、嚴重改用琥珀與紅色 |

## 二、一流前端怎麼做

| 參考 | 值得學的地方 | 套用 |
|------|------------|------|
| Apple 天氣 | 最上方一句話描述現況，視覺本身就是資料（天空、溫度條）；次要資訊收進可展開區塊 | 頁首一句話結論；水位刻度牆本身就是資料 |
| Linear | 克制的配色、緊湊但不擁擠的清單、完整鍵盤操作 | 清單式列而不是一格一格卡片；所有互動可用鍵盤 |
| Vercel（Geist） | 中性灰階＋單一強調色、數字使用等寬數字（tabular figures） | 所有數字 `font-variant-numeric: tabular-nums`，避免更新時跳動 |
| Stripe | 數字格式化嚴謹，單位小一級、顏色淡一級 | 單位（%、萬 m³）縮小並用次要色 |
| Windy | 色階一定配圖例；圖面優先 | 刻度牆上畫 30%、50% 參考線並附文字說明 |
| Observable Plot | 直接標註取代圖例、軸線退到背景 | 刻度牆直接標水庫名稱與數值，不另放圖例 |
| Radix Colors | 每個色相 12 階並各有用途，深色模式另有一組，不是反轉 | 深色模式各自挑選、各自驗證對比 |
| shadcn/ui、Tailwind、Design tokens（W3C DTCG） | 用語意化 CSS 變數（`--surface`、`--ink-2`）管理主題；4px 間距尺度 | 不引入建置工具，直接以 CSS 自訂屬性實作 token |

### 實測：標竿網站的字級與焦點

第一版上線後，使用者的回饋是「沒有視覺焦點、沒有對齊、字太小」。這一輪改用同一支 audit 腳本實測標竿網站，再拿同一支腳本驗收自己的頁面（2026-10-22，Playwright Chromium，量的是畫面上看得到的文字）。

| 頁面 | 寬度 | <14px 字元 | 主要字級 | 首屏最大 → 第二大 | 左緣分布（x：區塊數） |
|------|-----|-----------|---------|----------------|-------------------|
| Linear 首頁 | 1440 | 45% | 15px 25%、13px 23% | 64 → 64（同一標題拆三行），其後 20 | 48：35、0：16 |
| Linear 首頁 | 390 | 47% | 15px 28%、12px 27% | 38 → 38 | 16：30、0：25 |
| IQAir 台北 | 1440 | 7% | 16px 57%、18px 13% | 36 → 18（2 倍） | 232：24、0：15 |
| IQAir 台北 | 390 | 5% | 16px 65%、14px 26% | 28 → 16 | 16：26、64：21 |
| 本站改版前 | 1440 | 43% | 15px 48%、13px 30% | 26 → 25.2 | 132：66、116：45 |
| 本站改版前 | 390 | 45% | 15px 48%、13px 30% | 25.2 → 22 | 32：86、16：51 |
| **本站這一輪** | 1440 | **0%** | 16px 54%、14px 38% | **96 → 36（2.7 倍）** | **100：121**、0：2 |
| **本站這一輪** | 390 | **1%** | 16px 53%、14px 39% | **64 → 28（2.3 倍）** | **16：147**、207：18（水尺牆內的分區） |

Electricity Maps 也在名單上，但實測時被機器人驗證頁擋下，沒有數據。

學到的三件事：

1. **焦點靠比例，不靠顏色**。Linear 的標題是內文的 4 倍以上；本站第一版的總蓄水率雖然有 56px，但數字和「%」放在同一個節點裡，實際上第一眼看到的是好幾個 20–26px 的字在互相競爭。
2. **資訊型網站的內文是 16px**。IQAir 這種要讓一般民眾讀數字的網站，16px 以上占六成以上、小於 14px 不到一成；Linear 的小字多，是因為它是行銷頁的介面截圖，不適合照抄。
3. **對齊來自少用內距卡片**。IQAir 與 Linear 都讓絕大多數區塊貼齊同一條左緣；本站第一版每張卡片各有內距，左緣因此分成兩條。

不採用 React／Tailwind 的理由：這個網站只有一頁、20 座水庫，加入建置流程會讓 GitHub Pages 部署變複雜，而效能與可維護性的收益很小。設計系統的精神（token、語意命名、元件狀態）用原生 CSS 就能做到。

## 三、設計語言

### 設計構想：水尺牆

水利工程裡，水尺是立在水中的刻度板。首頁主視覺是一面「水尺牆」：20 座水庫由北到南排成 20 根直立水柱，水位高度就是蓄水率；名稱用直書標在水柱下方。直書在中文裡自然、在窄螢幕又剛好放得下 2–4 個字，讓 20 根水柱在 390px 手機上也能完整並排，不需要橫向捲動。

這是整頁唯一「大膽」的地方。其餘部分（清單、摘要、說明）保持安靜、對齊、數字優先。

### 色彩

| Token | 淺色 | 深色 | 用途 |
|-------|-----|-----|------|
| `--bg` | `#FFFFFF` | `#0B1824` 深水 | 頁面背景 |
| `--surface-2` | `#F2F6F9` | `#12263A` | 標籤、圖表底色、頁尾 |
| `--ink` | `#0F2333` | `#E4ECF2` | 主要文字（對比 16.1／15.0） |
| `--ink-2` | `#46596A` | `#A6B8C7` | 次要文字（7.3／7.8） |
| `--water` | `#2B79B0` | `#4FA3DC` | 水位（充足、正常） |
| `--low` | `#B26B00`（文字 `#8A4F00`） | `#F2A33A` | 偏低 30–50% |
| `--critical` | `#D03B3B`（文字 `#A82424`） | `#FF7070` | 嚴重 <30% |

對比數字由腳本以 WCAG 公式計算（文字 ≥ 4.5、圖形 ≥ 3）。狀態色一律搭配「偏低」「嚴重」文字，不單靠顏色。

### 字體

- **中文**：系統字（蘋方、思源黑體／Noto Sans TC、微軟正黑體）。不下載中文網頁字型：一套繁中字型動輒數 MB，會直接拖垮手機的 LCP。
- **數字**：Barlow Semi Condensed（SIL OFL）。半窄體的數字讓 20 根水柱上的百分比放得下，又帶點工程標示牌的語感。只保留數字與 %、+、−、:、/ 這些符號，500、600 兩個字重各約 4KB，自行託管在 `assets/fonts/` 並 preload，不依賴第三方、也不阻塞第一次繪製；使用 tabular figures。
- **字級階梯**：12／14／16／18／22／28／36／64／96px，不出現階梯以外的數值。
  - 96（手機 64）：全台總蓄水率，唯一主焦點。
  - 36（手機 28）：主焦點的「%」。28：區段標題、清單裡每座水庫的蓄水率。22：主焦點上方的標籤、側欄數字。
  - 18：結論句、水庫名稱、側欄標題。16：內文與所有可點的控制項。14：次要說明（縣市、時間、單位、圖說）。
  - 12：只用在水尺牆的參考線刻度，以及手機上水柱頂端的數值（圖表標註）。
- 行高：中文 1.65，數字 1.0。

### 間距、圓角、陰影

- 間距只用 4／8／12／16／24／32／48／64。水尺牆內 2px 的水柱間隙屬於圖形本身。
- **單一容器**：頁首、主內容、頁尾共用 `width: min(1240px, 100% - 2 × gutter)`，gutter 手機 16px、桌面 32px。桌面用 12 欄格線，主欄 8 欄、側欄 4 欄。
- **主欄沒有內距卡片**：總蓄水率、水尺牆、清單都貼齊同一條左緣；清單改成以細線分隔的對照表，側欄區塊以上方細線分組。水尺牆的參考線刻度移到右側，水柱才能從左緣開始。
- 圓角只留給膠囊（篩選、狀態標籤）、水柱頂端與錯誤提示框。不用陰影。

### 動效

- 首次載入不跑進場動畫，資料一到就直接顯示最終水位：水情頁的第一印象必須是「資料在這裡」，而不是一段等待。等待 API 時水尺牆中央會寫出「正在讀取水利署資料」。
- 之後每次資料更新，水位用 300ms ease-out 過渡到新高度，讓變化看得見。
- 使用者操作有回饋：展開列、切換篩選、重新整理按鈕旋轉。
- `prefers-reduced-motion: reduce` 時全部停用。
- 水位只在資料真的變動時才重新動畫，避免每 5 分鐘自動更新時整頁閃動。

### 對照生成式預設的修正

初稿是「大數字＋三張統計卡＋卡片網格＋漸層」，這正是各種儀表板的預設樣子，也接近舊版。修正為：

1. 統計卡改為**一個主焦點**（全台總蓄水率）加一句結論。
2. 卡片網格改為**分區清單**，每列資訊密度一致，好掃讀。
3. 長條圖改為**直書水尺牆**，同時解決「總覽」與「地理位置」兩件事。
4. 不用全大寫英文小標、不用等寬字型標數據、不用漸層裝飾。
