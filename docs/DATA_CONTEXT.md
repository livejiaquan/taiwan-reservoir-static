# 水庫資料範圍與時間語意

## 本批範圍

保留原生 HTML/CSS/JavaScript 與 Chart.js，不更換框架、不增加後端，也不發布到正式站。重點是讓讀者知道資料的時間、範圍、限制與計算方式。

## 官方來源

- [水庫水情資料](https://data.gov.tw/dataset/45501)：`reservoiridentifier`、`observationtime`、`effectivewaterstoragecapacity`，水量單位為萬立方公尺。
- [水庫每日營運狀況](https://data.gov.tw/dataset/41568)：`reservoiridentifier`、`datetime`、`capacity`，有效容量單位為萬立方公尺。每日登錄與水量觀測的時間語意不同，不能以網頁擷取時間代替。
- 實際 API URL 保留在 `js/api.js`。2026-09-30 從雲端工作環境讀取小樣本，確認上述小寫欄位與時間字串存在；也觀察到空字串與負值哨兵，因此不把它們轉成零或正常資料。這項檢查不代表所有站點或瀏覽器 CORS 已驗證。

## 行為契約

1. 未附時區的來源時間明確按台北 UTC+8 解析；附有 `Z` 或偏移時尊重原始時刻。拒絕不可能的日期，保留毫秒排序。所有顯示時間使用 `Asia/Taipei`。
2. 依真正時間選取各庫最新水量觀測與最新有效容量記錄。無法判讀的容量時間明確顯示「時間未知」，不以水量或擷取時間補造。
3. 成功網路擷取時間保存在 v4 快取；讀取快取不重新標成剛更新。失敗時沿用既有 fail-closed 行為，清除數值與快取，不顯示過期或模擬水情。
4. 20 座站點是本站對照清單，並非全台完整清單。少於 10 座不顯示快照；10–19 座會顯示缺席水庫清單。東部尚未被納入，而不是被判定為 API 故障。
5. 水量觀測超過 6 小時加註提醒，超過 48 小時或超前 1 小時拒絕整份快照。以上為本站規則，不是官方服務保證或水情警戒門檻。容量資料時間另列，未宣稱與觀測同時更新。
6. 合計與地區合計都使用蓄水量總和 / 有效容量總和。個庫超過 100% 的原始計算值保留；進度條只限制繪圖範圍，Chart.js 座標軸可延展。
7. 蓄水率區間只是一種分組；不聲稱足以判斷季節異常或供水風險。未接入真實歷史資料前，歷史圖函式不產生圖表或隨機資料。

## 研究取捨

參考 CQD 的季節脈絡問題意識，但未複製其程式碼；未引入舊 D3/jQuery 或 Ionic/React 技術棧。歷年同期比較留待有可驗證來源與完整資料後再設計。本批優先修正資料語意與手機重要文字可讀性。

## 驗證界線

- Node 內建測試：來源格式、時區、加權計算、快取、資料拒絕、render 字串與 Chart.js 設定。
- 靜態資產存在與 JavaScript 語法檢查；沒有獨立 build 步驟或 CI workflow。
- 雲端預覽受既有 loopback/受支援代理路徑限制，未繞過限制；本批沒有瀏覽器視覺或行動裝置實機通過的宣稱。合併前仍應檢查正常、部分資料、失敗、東部篩選與重複刷新畫面。


### 單次 API 整合抽查（2026-09-30 19:31 UTC）

透過雲端環境讀取既有兩個 API（`size=1000`），分別收到 464 筆水量資料及 59 筆容量資料。以本批解析器合併後有 19/20 座清單內水庫，該次未顯示永和山水庫，容量時間皆可解析，且通過既有新鮮度／覆蓋門檻。此為有時間界線的單次整合檢查，不是持續可用性保證，不代表瀏覽器 CORS 或正式站已驗證；未將抽查水情保存為正式資料。
